# NTPU One 使用者流程與 UI/UX 檢查

檢查日期：2026-11-04。程式基準：`e5662eb`（1.4.0 build 41）。

本次閱讀首次導覽、帳號與學校同步、首頁、課表、備忘錄、成績與畢業門檻、Moodle、AI 聊天／資料權限／附件／變更預覽的主要流程。以下區分程式中可確認的行為與設計建議；不是所有服務的實機驗收結果。模擬器目前安裝 build 31，其截圖只作版面參考，不能證明 build 41 的實際畫面。未以真實校務帳號逐頁測試、未重新上傳版本。

## 優先修正：流程與資料安全感

### 1. Google 登入成功可能提早結束整個新手導覽（P1）

- 位置：`NTPUOne/ContentView.swift:419`。
- 可確認：導覽的 task 偵測已登入或恢復 Firebase session，等待 400ms 後直接呼叫 `onFinish()`，沒有以目前是否位於 Google 登入步驟作為限制。
- 影響：原本只需跳過 Google 登入頁，卻可能連學校系統與 AI 的介紹都跳過。重播導覽已透過 `autoFinishAfterAuth: false` 分開處理，應保留。
- 建議：登入結果只完成「帳號」這一步；新手導覽、登入提示、學校連結提示各自持有完成狀態。已登入者跳過 Google 步驟，仍保留未看過的介紹。
- 驗收：訪客首次開啟、已登入首次開啟、導覽中完成登入、設定內重播，四條路徑都能到達正確下一步。

### 2. 學校連結的訪客入口缺少可操作的下一步（P1）

- 位置：`NTPUOne/Academic/AcademicViews.swift:60`。
- 可確認：尚未登入 Google 時，此頁只顯示「請先在『我的』登入 Google 帳號」，沒有直接登入按鈕；已登入時才提供學校帳密表單。
- 建議：就地顯示「登入 Google」，完成後回到原本的學校連結頁。不要要求使用者記住文字指路再跨分頁尋找。
- 學校與 Moodle 目前已有登入進度；下一步應補上各自成功／失敗／最近同步時間、失敗服務單獨重試，以及「連結成功但尚未匯入課表」等狀態的區分。
- 驗收：其中一個服務失敗時，不需要把成功的服務重新登入一遍；使用者看得懂目前能使用哪些資料。

### 3. AI 單筆與整批確認沒有共用的已套用狀態（P1）

- 位置：`NTPUOne/AIAssistant/FloatingAIView.swift:637`、`NTPUOne/AIAssistant/AIChangeReviewView.swift:170`。
- 可確認：整批儲存會設定 `batchApplied`；單筆確認沒有回傳完成狀態給訊息卡片，單筆新增會產生新 UUID。訊息用「請勿再次整批套用」與「每次確認都會執行一次」提醒使用者。
- 影響：單筆預覽仍可重複進入；介面無法可靠呈現哪些提案已經執行，也不能單靠警告文字保證不重複新增。整批已有部分重複檢查，不代表單筆與整批狀態已統一。
- 建議：每個提案有穩定 ID 與待確認／已套用／失敗狀態；整批只執行尚未套用項目。成功後卡片顯示實際儲存的課程連結、提醒時間與「查看備忘錄」。
- 驗收：單筆儲存後再進預覽、接著整批確認、重新開啟聊天，都不重複新增同一提案。

### 4. 批次變更預覽仍要求輸入技術格式（P1）

- 位置：`NTPUOne/AIAssistant/AIChangeReviewView.swift:295`。
- 可確認：批次編輯的截止時間是 ISO8601 文字輸入；課程選單逐筆列出課表項目，同一門課不同節次可能重複出現。單筆已使用較原生的日期編輯方式。
- 建議：統一使用日期／時間選擇器；明確區分「保持原值」「設定時間」「移除時間」。每筆先顯示名稱、連結課程、截止時間、提醒時間，展開才顯示次要欄位。課程依同一課程整理，必要時才展開節次。
- 驗收：不用理解 ISO8601 就能修改五筆提醒；沒有配對到課程時，明確顯示「尚未連結」並可當場選擇，不能只靠 AI 的敘述宣稱已連結。

### 5. 三種帳號狀態需要同一套說明（P1）

- 位置：AI 標頭、`FloatingAIView` 的帳號卡片、學校連結頁、`NTPUAIWebBridge`。
- 可確認：App Google 帳號、手機保存的學校登入資料、AI 網頁 session 分別管理；AI 的「已連線」不足以解釋三者關係。
- 建議：一張精簡狀態卡顯示「App 帳號」「學校資料」「AI 連線」。每列只提供對應的登入／更新／登出操作；可取得時顯示遮罩帳號。清除 AI 網頁登入時，清楚說明影響範圍。
- 驗收：Google 登出或切換後，使用者能理解哪些個人資料不可用、AI 網頁是否仍登入；不得讓另一個 App 帳號繼續取得前一位的個人資料。

## 第二階段：簡化每日操作

| 項目 | 現況或風險 | 建議 |
| --- | --- | --- |
| 首頁資訊順序 | 今日區塊包含課程、預設收合的待辦與餐廳推薦；重要任務容易需要額外點擊 | 第一屏顯示下一堂課、最多三筆逾期／今日待辦；餐廳縮成次要卡片，公告與快捷入口保有穩定位置 |
| 備忘錄篩選 | `TodayView.swift:167` 的「已完成」會直接改成完成列表，覆蓋目前日期分頁內容 | 讓日期與狀態篩選共同生效；或清楚切換成獨立「已完成」頁，避免分頁名稱與內容不一致 |
| 備忘錄誤刪 | `TodayView.swift:1086` 允許完整滑動直接刪除；`MemoManager.swift:237` 立即刪除並儲存 | 刪除後提供短暫「復原」；大量刪除使用明確預覽。現有完成狀態復原不能代替刪除復原 |
| 課表刪除 | 清空課表也會處理連結備忘錄，影響範圍大 | 預設保留備忘錄並解除連結；另提供明確選擇同步刪除，顯示筆數與結果 |
| Moodle 課程詳情 | 原生內容、單項網站入口與完整課程網站入口並存 | 維持四分頁的共同版型；教材加搜尋、檔案類型與大小；公告顯示日期與閱讀狀態；網站入口統一標示「以校方網頁開啟」 |
| 成績／畢業門檻 | 登入失效、尚無資料、更新失敗都需要不同下一步 | 空白狀態提供直接連結／重新登入／重試按鈕；學分統一「已修／應修／尚缺」，未提供值用「—」並說明，不推算成零 |
| 資料更新 | 各資料來源更新頻率不同，使用者不易判斷是否過期 | 各主要頁顯示最後成功更新時間；失敗時保留資料並標示使用快取，提供當前區塊重試 |

## AI 對話流程

1. **首次進入**：保留第一次就詢問資料授權的需求，但以精簡 toggle 區塊呈現，細節可展開。保持原有的權限預設，不為了簡化而擴大授權。
2. **提問前**：讓使用者能立即看到目前允許使用哪些資料；缺少權限時提供對應設定入口，避免反覆解釋整段權限文字。
3. **處理中**：區分「讀取 Moodle」「下載附件」「上傳檔案」「等待回答」。顯示可取消狀態，失敗時可重試同一問題及附件。
4. **回答後**：資料來源與更新時間收成可展開的短標籤；只有真正有頁面或變更可操作時才放主要按鈕。控制單則訊息中的按鈕數量。
5. **新增／修改前**：使用原生預覽顯示實際將儲存的值，尤其課程連結、日期與提醒。AI 敘述與預覽不一致時，以驗證過的提案內容為準並告知使用者。
6. **儲存後**：原卡片轉成成功狀態，提供「查看」，不繼續留一個能重複執行的確認按鈕。

附件部分還應補：Moodle 附件清單的失敗重試、沒有課程時直接前往同步的入口、自動選檔的檔名與課程來源，以及超過大小／數量限制時的具體原因。不要讓「找不到」與「只搜尋了部分資料」呈現同樣的空白結果。

## 建議統一的視覺規則

- 每頁一個主要操作；次要功能放選單，破壞性操作獨立分組。
- 卡片採共同的標題、摘要、狀態、操作順序；避免卡片裡再包多層背景卡片。
- 使用者看日期應是「11 月 5 日（四）23:59」等本地格式，保留 ISO8601 給程式交換資料。
- 所有只有圖示的可點擊按鈕補齊輔助使用名稱；觸控範圍與字級放大後的排版逐頁確認。
- 深淺色皆檢查文字、聊天泡泡、提示卡與玻璃背景對比。沿用既有減少動態效果／減少透明度處理，補足逐頁驗收。
- 一般手機維持單頁操作；展開寬畫面才使用內容與 AI 並排，並確認鍵盤不擠壓主要操作。

## 下一輪驗收清單

- 訪客 → Google 登入 → 回到原頁 → 連結學校 → 部分成功／全部成功。
- 已登入首次啟動與手動重播新手導覽；遠端關閉 AI 時不出現 AI 教學。
- AI 提案：單筆、整批、重複點擊、手動改課程、沒有唯一課程、儲存失敗與重新開啟聊天。
- Moodle：無課程、公告無附件、PDF／圖片／Office、逾時、超過限制、session 過期、取消上傳。
- 離線、舊快取與重新連線；個人帳號切換後資料隔離。
- 一般手機／Duo 外螢幕／展開／旋轉、鍵盤開關、深淺色、大字級、VoiceOver、減少動態效果。

建議先完成第 1–5 項流程問題，再統一每日操作與視覺版型；每輪以以上情境驗收，避免只以編譯成功判定 UX 完成。
