# 課程詳情與 Moodle 內容整理（build 23）

- 課程詳情以課程資訊、Moodle、課程待辦三個一致區塊呈現。Moodle 使用單一入口再切換公告、教材、作業、成績；配對、學校帳號、待辦分類排序與新增功能保留，外部課程網站收在「更多課程連結」。
- 公告以標題與摘要閱讀，可展開完整內容；教材按單元收合，單元下分開列出文字、原生附件及 Moodle 網頁入口；作業依截止時間排序並標示提交狀態；成績以名稱、數值與可展開回饋呈現。各頁保留原本重新整理與空白／錯誤狀態。
- Moodle 原生檔案按鈕與網頁按鈕改為各自的 borderless 按鈕，避免 List 同列自動按鈕樣式將多個動作一起觸發。網頁視窗關閉或帳號範圍改變時清除預覽狀態，並以每次呈現的識別碼拒絕遲到的下載回呼；被拒絕的暫存檔會清除。WebView 銷毀時仍取消未完成下載。
- 遵照既有身份與資料存取限制；不代使用者登入 Moodle 網頁，原生預覽仍使用既有經核准 API。合成與編譯檢查不等同於真實 Moodle session、檔案與實機手勢測試。
- 已取得使用者去值 SAML 登入診斷，並核對公開官方表單，新增使用本機已保存學校帳號登入 AI 的按鈕。真實手機首次登入與教材開啟仍需 TestFlight 驗收，詳見 `AI_LOGIN_TEST.md`。

## build 24：重新安裝與連結

首次 Google 登入依有效的 Firebase 身分及 Google 登入完成回呼自動結束提示，稍候官方頁面收回後再完成導覽；科系選擇留在個人頁處理，不阻擋進入 App，同時處理畫面剛出現就已有 Firebase 工作階段的情況。學校連結自動提示改用與 Google 提示一致的圖示、卡片、主按鈕及稍後操作，完整帳密表單由主按鈕開啟。

Keychain 憑證存在不再顯示成已同步。重新安裝後身分／Moodle 使用者快取缺失，會從經校方驗證的回應重建；已有身分或另一服務身分不同時仍拒絕。不可讀的快取移至同一受保護目錄的 recovery 檔再重建；保存失敗時仍回報錯誤，手動連結可重新嘗試，不會永久被 storageAvailable 鎖住。

校務與 Moodle 分別嘗試連結，不因前者失敗直接跳過後者。公開課程查詢失敗時，已通過本人／學期／核准狀態驗證的正式課號仍可用來核對 Moodle；同學期舊詳情可暫時保留，其他欄位標示待更新，不猜上課時段，也不自動匯入空白時段。同步錯誤與更新時間保留在設定頁。
