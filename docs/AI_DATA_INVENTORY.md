> build 21 更新：在原有 18 類以外新增本機通知設定、餐廳公開評論、公告圖片，共 21 類；以下 build 20 清單保留作歷史紀錄，以本段與文末更新為準。

盤點日期：2026-11-02；以下 AI 狀態已更新至 build 20 實作（真實登入與實機資料取得仍待驗證）。這份清單依專案原始碼整理資料種類與程式可能讀取的來源，**不是**雲端資料庫的完整實際結構、權限清單或使用者資料匯出；未讀取個人紀錄、帳密或雲端後台。Firebase 規則、校方 API 權限與服務是否開放，仍需要各自驗證。AI 不能因為資料存在就自動取得：下表的「現況」指本版程式，而不是未來保證。

## 可供使用者問題使用的資料

| --- | --- | --- | --- |
| 個人課表 | Core Data `CourseEntity`，配置 CloudKit 私人同步；課名、星期、節次、地點、教師、提醒 | 本機讀取及 CloudKit 同步；校務核對後另可匯入 | **已接入** `courses`；有筆數與字數上限；非 iCloud 全庫掃描 |
| 備忘錄、待辦、排程 | Core Data `MemoEntity`，配置 CloudKit 私人同步；標題、內容、類型、關聯課程、期限、狀態等 | 本機讀取及 CloudKit 同步 | **已接入** `memos`；最多 50 筆，個人內容可能敏感，需使用者啟用 App 資料模式 |
| 正式修課與學期 | 校務正式選課；學年、學期、課號；再以公開課程目錄補課名、教師與時段；存於帳號隔離的本機 Academic 快取 | 連結後、前景檢查滿 30 日或學期變化、手動強制 | **已接入** `enrolment`，使用帳號隔離的正式學期／課號快取並附更新時間。 |
| 成績、學期排名 | 校務只讀查詢後解析的本人原生報表、學年學期與成績欄位，本機受保護快取 | 前景檢查報表約 24 小時、手動強制或進入報表頁 | **已接入** `schoolGrades`／`ranking`，須另啟用成績資料；只用原生解析的本人報表，不以缺值推算成績。 |
| 畢業門檻、學分 | 校務畢業檢核與學分分類、狀態及總計，本機受保護快取 | 同上 | **已接入** `graduation`，須另啟用；附校方結果時間，不代替校方資格審查。 |
| Moodle 作業 | Moodle API 的課程、作業描述、截止、個人或團隊提交狀態；同步到受保護 Academic 快取，也可合併到本機備忘錄 | 前景檢查距上次成功至少 5 分鐘、手動；須先核對正式學期及課號 | **已接入** `moodleTasks`，直接整理已核對的作業快取、截止、提交／團隊／來源狀態。 |
| Moodle 公告、教材、作業詳情、課程成績 | 課程內容 API、news 論壇 API、本人已公布成績；本版嘗試以 Web Service token 原生讀取受允許的附件 | 開啟課程分頁或下拉重新整理；附件依需要下載 | **已接入** `moodleContent`／`moodleGrades`；依關鍵字挑選已核對課程，最多 8 門。包含公告、教材說明、檔名及 API 直接提供的文字；不自動上傳檔案全文。成績須另外啟用。 |
| 首頁公告與活動 | Firestore `order`；公告內容、發布者、時間、類型、連結等 | 首頁顯示時 Firestore snapshot listener；離開後可能只剩最後快照 | **已接入** `announcements`，AI 會獨立讀取最新最多 30 筆公開公告，不依賴首頁 listener 是否顯示；不附聯絡信箱與擁有權資料。 |
| 校方官方新聞 | NTPU Strapi GraphQL；標題、內容、標籤、發佈時間、附件、圖片，現有畫面查詢最多 20 筆、非活動 | 進入校園新聞頁時抓取 | **已接入** `officialNews`，讀取最多 20 筆公開新聞，包含標題、摘要、時間、標籤及附件名；不是全站搜尋。 |

| YouBike | 新北開放資料；站名、座標、總車位、可借、可還；目前篩選北大中心 2 公里內 | 進入站點頁及手動；AI 選此類時超過 60 秒會嘗試刷新，失敗保留舊快照 | **已接入** `bikes`；最多 40 站並帶上次成功更新時間；狀態即時性仍依官方資料 |

| 餐廳評論 | 各店 `comments` 子集合、本人擁有權索引及 userStats | 對應店面／個人評論畫面查詢或 listener | **未接入**；涉及他人發文及個人索引，應先確認對話情境、最少欄位與授權，不傳聯絡或裝置識別資訊 |
| 社群貼文與回覆 | Firestore `communityTopics` 與 `replies`；文字、類別、時間、互動等 | 開啟交流區時 listener | **未接入**；第三人內容與隱私，應只處理使用者明確選取、可見且必要的內容 |
| 社群圖片 | CloudKit **公開**資料庫的圖片紀錄與本機記憶體快取；不是私人課表的 CloudKit store | 依貼文需要下載／上傳 | **未接入**；不能把圖片或他人資料自動上傳模型，需獨立處理附件與權限 |
| 我的社群內容、喜歡、個人資料 | Firestore `communityContentOwners`、`communityUserLikes`、`communityUserProfiles` 等及部分本機偏好 | 登入後依畫面查詢／互動 | **未接入**；個人與他人資料混合，應單獨選擇，避免洩漏 UID、裝置標識與第三人資訊 |

| 校園設施、快捷連結 | 程式內靜態清單、部分校園地圖資料 | 隨 App 版本；可能另有動態來源 | **已接入** `campus`，使用 App 內建設施與公開網站清單，不使用個人定位；只提供連結，不自動讀取網站。 |
| 公開課程查詢 | 校方課程目錄搜尋及 Firebase `CourseYear` 年度資料 | 課程搜尋或學年選單載入時 | **已接入** `courseCatalog`，使用 Firestore 學年設定與校方只讀關鍵字搜尋，需至少兩字課名／課號；限目前學期最多 40 筆，與本人選課分開。 |

## 不應成為聊天資料的來源

- 學校帳號密碼、Moodle token、AI 網站 Cookie／Session、管理員密碼、Firebase／CloudKit 登入憑證、天氣 API 存取識別碼。這些是登入或服務設定，不是聊天資料。
- 推播／裝置識別資料：如 `communityDeviceTokens`、分類與貼文訂閱；`userStats` 及索引可能含個人標識。不可因查詢公告而一併傳送。
- 管理與營運資料：`bug`、`feature`、管理員工具、檢舉處理、Remote Config、廣告狀態等。可能包含使用者聯絡資料或非公開內容；一般助理不直接查取。
- 原始校務 HTML、未知第三方網址及未核對來源。分類器輸出只能在程式內的明確允許類別中選取；來源文字不是可執行指令。

## 本版分類器與限制

`AIDataSource` 有 18 類：`courses`、`memos`、`enrolment`、`moodleTasks`、`moodleContent`、`moodleGrades`、`schoolGrades`、`ranking`、`graduation`、`announcements`、`officialNews`、`calendar`、`weather`、`bikes`、`restaurants`、`preferences`、`campus`、`courseCatalog`。成績類的四項來源預設不授權，必須在 AI 選單另外啟用；分類器收到的允許清單與實際執行層都會過濾未授權類別。

啟用 App 資料後，模型只選來源及最多 80 字的課程關鍵字，手機負責固定的只讀查詢。模型不能提供網址、Firebase 路徑、SQL、Shell 或任意工具。每類快照有字數、筆數和來源時間，總量上限亦會標示截斷；公開來源快取 5 分鐘，餐廳 10 分鐘；YouBike 超過 60 秒嘗試更新。失敗時明確標示缺資料或舊快照。分類及回答為兩次模型請求，校方服務可能保存兩次內容。

撤回資料授權會中止請求並讓下一則開始新網站對話；不會自動刪除校方已保存的對話。CloudKit 來源限這個 App 已載入的私人課表與備忘錄，不會掃描其他 App 或整個 iCloud 帳戶。

## 暫不自動串接，供使用者決定

| 項目 | 暫緩原因 | 可考慮的後續方式 |
| --- | --- | --- |
| 社群貼文、回覆與餐廳評論 | 含第三人內容與可能的個資，不適合隨問題大量外傳 | 由使用者明確選取單一公開內容後，去識別化整理 |
| 社群圖片與教材／附件全文 | 可能含第三人、著作權或個人資訊，圖片也需要多模態流程 | 每次由使用者選檔及確認，限定大小、類型和用途 |
| 社群個人檔案、發文／喜歡／評論擁有權索引 | 包含 UID、個人識別或關聯資料，通常不是解答所需 | 如有需求只提供本人選定、去識別化的欄位 |
| 裝置 token、帳密、Cookie、管理員資料、API 憑證 | 是安全或登入資料，不是可用來回答問題的內容 | 用於各自正常登入流程，永不作為模型資料集 |
| Bug／功能建議、後台處理、營運設定與廣告資料 | 可能含聯絡資訊、管理權限或未公開內容 | 如需管理助理，另做權限與操作確認流程 |
| 原始校務 HTML、任意網站抓取與模型產生的指令 | 未核對內容、驗證或執行範圍不可控 | 使用已核對 parser／API；新增來源需單獨定義 |

校務與 Moodle 本人成績已可串接，但需獨立開關；它們不是上述永久排除項目。歷史紀錄：當時模型沒有資料變更能力；build 25 的受確認預覽流程見文末。

## build 21 更新

- 本機通知設定：讀取 iOS 通知授權、提醒／聲音／徽章狀態、課程及備忘錄提醒數、交流區通知功能狀態；不傳送裝置 token 或通知全文。
- 餐廳公開評論：依問題中的至少兩字店名搜尋每餐別前 100 店，最多各取 3 間及各店最新 10 筆；只傳文字，不傳作者或裝置識別資料。未匹配不代表不存在。
- 公告圖片：需問題提供至少兩字公告名稱，從最新 30 筆圖片公告中取第一個符合項，僅接受 `cms-carrier.ntpu.edu.tw` HTTPS 且不跟隨重新導向；讀取最多 4 MB、轉為 JPEG 後透過 NTPU AI 官方頁上傳一張。網站未成功顯示附件時取消本次送出。圖片及其中內容會傳至校方，啟用 App 資料前應先告知。模型分類、校方附件 UI、私人 Firebase 權限和圖片理解皆需真實手機驗證。
- AI 頁面目錄與固定跳轉見 `docs/AI_PAGE_GUIDE.md`；模型僅能選 App 定義的頁面代碼。聊天畫面首次開啟會詢問資料授權，成績另行啟用。
- 其他第三人資料如社群貼文及回覆、社群圖片、個人檔案及識別索引不因上述變更而自動加入。餐廳評論與公告圖片已獲使用者指示納入，不再適用前述「暫不自動串接」的舊表格描述。

## build 22：前景提醒與授權 Toggle

新增進入 App 時的唯讀提醒。未開啟 App 資料時，只讀公開天氣與當前餐別餐廳；已開啟時另整理近期課程和未完成待辦。提醒不讀成績、圖片、附件或評論，也不要求 iOS 通知授權。30 分鐘內不重複成功提醒；只在前景和既有 AI 登入有效時嘗試，不能保證離線或未登入時有 AI 回覆。

首次進入聊天改為顯示三個 Toggle 的資料設定頁。App 資料、成績與畢業資料、提醒開關按 App 帳號在本機保存並沿用下次聊天；校方 AI 身分變更時撤回私人分享。停用 App 資料同時停用成績。選單加入新對話，保留資料設定。資料授權不是 iOS 系統通知權限；完整範圍與節流見 `docs/FLOATING_AI.md`。

## build 25：分項授權與資料變更

私人資料可分別控制課表、備忘錄、Moodle、校務及成績；首次安裝本機課表與備忘錄預設開啟，其他私人來源預設關閉。各來源仍受總開關、登入狀態、取得結果與資料上限限制。撤權後不再提供新資料。模型提出課表或備忘錄變更時，App 僅顯示可編輯的原生預覽，由使用者確認後執行；不直接執行模型產出的內容。上述新版規則取代舊 build 記錄中有衝突的授權和寫入說明。
